# Web UI 阶段 5.2.2：前台文案与标题层级收口

日期：2026-09-01
范围：`master` 分支；延续阶段 5.2 的视觉与页面架构，收口阶段 5.2.2 前台文案与标题层级，不修改 LPC、`mudcore` 或玩法规则。

## 1. 视觉方向

本阶段继续以已确认的 5.2 手机端与电脑端江湖页为统一基线：深色墨色背景、暖金标题与边框、青色交互状态、水墨山水纹理、中文标题字体与紧凑信息卡片。没有回退到旧版 sidebar + drawer，也没有重新设计另一套风格。

## 2. PC 页面结构

桌面江湖页保持顶部全局导航、左侧人物/战斗栏、中间原版文字终端、右侧房间/实体栏和底部主导航。页面化的行囊、装备、武学、任务、消息、地图和帮助页继续共用同一套页面表面、标题和底部导航视觉。

## 3. 手机页面结构

手机端保持顶部品牌与连接状态、单列江湖内容、房间/实体/战斗面板纵向排列，以及底部五项主导航。`390 × 844` 和 `844 × 390` 都使用安全区内边距与面板内部滚动，命令栏仍固定在江湖内容底部。

## 4. 江湖页面

人物、战斗、房间、实体和终端均只渲染 `useMudClient` 收到的真实协议数据。人物卡使用通用人物 silhouette 作为装饰，不把它当作角色头像；没有姓名、等级、门派称号或侠义协议字段时不显示这些信息。房间标题只使用 `Room.Info.name`，区域只使用 `Room.Info.area`，出口使用真实 `exits`，详细描述继续由 Terminal 的原版 `look` 文字承担。

## 5. 行囊

行囊页只显示 `Char.Inventory` 的物品、数量、重量、分类和服务端动作。未连接时物品数组为空并显示“连接江湖后查看行囊”；已连接但快照为空时显示“行囊中暂无物品”。

## 6. 手机装备二级 Tab

手机底栏严格保持“江湖、行囊、武学、任务、消息”五项，不增加第六项装备。进入行囊页后显示“行囊 | 装备”二级 Tab；点击装备渲染同一真实 `EquipmentPanel`，底部“行囊”仍保持 active。桌面端继续保留独立的装备入口。

## 7. 武学

武学页使用 `Char.Skills` 与 `Char.Status.enabled/prepared`，只显示服务端返回的技能、等级、熟练度、启用和准备状态。没有快照时区分“连接江湖后查看武学”和“暂无武学数据”。

## 8. 任务

任务页只读取 `Quest.List`，使用真实任务状态、分类、详情、目标进度和完成记录。未连接时不展示任务记录；任务角标由当前 `Quest.List.quests.length` 计算。

## 9. 消息

消息页只读取 `Chat.Message` 事件，并按当前 `Chat.Capabilities` 和 `Chat.Targets` 提供频道、说话、私聊与回复操作。未连接时显示“连接江湖后查看消息”；无目标时显示“当前没有可私聊玩家”。消息角标由当前消息数组长度计算，不使用演示消息。

## 10. 地图当前只是占位

地图页保留 5.2 的水墨背景、山水纹理、网格和罗盘视觉框架，页面标题为“地图”，正文显示“暂无地图数据 / 真实地图数据尚未接入 / 开发中”。当前没有城市节点、路线、假当前位置、自动寻路，也不会发送北/南/东/西移动命令。真实地图等待后续协议与阶段接入。

## 11. 不显示假等级、经验百分比或安全区

`Char.Status.exp` 是战斗经验数值，不是升级百分比；人物卡按数值格式显示“战斗经验”，删除经验进度条。`status.potential` 按协议含义显示为“潜能”，不再标为“侠义”。当前协议没有公开等级、角色名、侠义或 `safe/no_fight/zone_type` 字段，因此不显示“48级”、客栈安全区等推测数据，也不根据经验猜等级。

## 12. preview 数据处理策略

本阶段直接删除 production 中的 `previewRoom`、`previewVitals`、`previewStatus`、`previewCombat`、`previewEntities`、`previewInventory`、`previewEquipment`、`previewSkills`、`previewQuests`、`previewCapabilities`、`previewTargets`、`previewMessages` 和 `previewSegments`，不保留自动 preview 模式。未连接时所有快照字段分别回到 `null` 或空数组，终端显示连接态空提示；重连和关闭连接时同步清空旧数据。顶部只显示真实连接状态和协议提供的 `connectionDetail`，不显示固定区服或 RTT。

## 13. Viewport 测试

已在应用内浏览器实际执行：

- `390 × 844`：移动竖屏连接态正常显示真实人物/房间数据；行囊/装备二级 Tab 可切换，底栏保持五项且装备页仍以行囊 active。
- `844 × 390`：移动横屏连接态没有横向溢出，命令栏可通过主内容滚动到达并位于底栏上方。
- `1440 × 900`：桌面三栏连接态、独立装备入口、真实行囊/装备数据和地图占位页均正常显示。

Vite 本地页面的断线空态、真实空列表文案、地图无移动动作和桌面/移动布局均已检查。通过 `http://127.0.0.1:8888/app/index.html` 完成了一次性本地角色注册、人物创建、登录和普通初始化流程（`look paizi`、`washto 20 20 20 20`、`born 扬州人氏`）。协议调试记录确认真实收到 `Char.Vitals`、`Char.Status`、`Room.Info`、`Room.Entities`、`Char.Inventory`、`Char.Equipment`、`Char.Skills`、`Combat.State`、`Combat.Actions`、`Quest.List`、`Chat.Capabilities`、`Chat.Targets` 及 `Chat.Message`；登录后页面显示真实的“战斗经验 0”“潜能 99”、客店房间、3 件行囊物品、2 格装备、1 项任务和频道消息。停止本轮驱动后，客户端从“重连中”稳定回到“未连接 / 重连次数已用完”，人物、房间、实体、行囊、任务和消息均被清空。一次性账号 save 与本轮 `log/debug.log` 已删除，没有保留可复用凭据或测试账号文件。

## 14. 自动化测试

在 `web-client` 目录执行：

```text
npm test -- --run
```

结果：15 个测试文件、56 个测试通过。新增 App 级回归覆盖断线空态、去除 preview 角色/房间/延迟/安全区、经验数值与潜能标签、地图不发移动指令、移动端装备入口、真实任务/消息角标，以及一级标题单份、中文标题和英文装饰眉题清理。

## 15. 生产构建

在 `web-client` 目录执行：

```text
npm run build
```

结果：`tsc --noEmit` 与 Vite production build 通过，生成并更新 `www/app/index.html` 及对应 JS/CSS 资源。

## 16. 已知限制

- 当前 Room.Info 没有结构化地图、房间描述或安全区元数据，因此地图仅占位，详细原版描述仍在 Terminal 中。
- 当前 CharacterStatus 没有等级进度百分比字段，经验只能显示为战斗经验数值。
- 当前协议没有角色头像、姓名、等级、侠义或门派称号字段，人物卡使用通用装饰和真实状态。
- WebSocket 登录仍依赖真实 FluffOS 会话；断线态不会用演示数据填充界面。
- 一次性本地账号仅用于本轮验收，账号 save、运行日志和凭据均未保留；后续复测仍应使用新的临时账号或正式测试账号。

## 17. 阶段 6 建议

后续可以在协议明确提供真实地图节点、路线、房间 metadata、等级进度或头像资源后，再分别扩展地图和人物信息；同时补充真实会话下的地图探索与多视口回归。阶段 5.2.1 不提前扩展这些协议或玩法。
