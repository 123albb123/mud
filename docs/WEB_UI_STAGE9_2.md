# Web Client Stage 9.2：最终 UI、响应式与交互收尾

## 范围

本阶段只处理 `web-client/src/**`、`web-client/public/**`、`web-client/index.html`、前端测试、`www/app/**` 和本说明文档。没有修改 LPC、GMCP schema、mudcore、游戏逻辑、Docker 配置或 Lucky 配置。

基线 commit：`ae10cdbd945787c560f7c0ebeba475e7fc9b1d37`

## 完成内容

- 移动底栏固定为六项：江湖、行囊、武学、地图、任务、消息；装备继续从桌面入口和行囊页进入。帮助入口保留在顶部导航，并从设置页复用既有 HelpView。
- 在 920px 及以下增加紧凑人物状态条，使用 `Char.Vitals`、`Char.Status` 和 `Combat.State` 的真实字段；左侧宽人物栏隐藏后，战斗面板仍保留为可滚动、可触达的独立区域。低高度横屏把战斗区前置，不用 `display: none` 丢失入口。
- 390px 竖屏和 844×390 横屏的表单控件统一至少 16px 字号、40px 高度；底栏、实体、战斗、武学、物品、地图和聊天操作保留触控尺寸，并禁止页面横向溢出。
- 切换附近人物/地面物品分组时清除人物选择、消息动作、消息草稿和赠送物品选择，避免旧 NPC 详情残留。
- 保留服务器下发的 NPC/玩家原始名称；战斗目标的 `value` 仍是 opaque `entity_id`，显示标签区分 NPC 与玩家。全为必选目标时显示“请选择目标”，存在可选动作时显示“不指定目标（可选）”。
- 将武学内部类型映射为内功、轻功、招架、剑法、刀法、拳脚等中文展示；任务内部分类映射为师门、江湖、大宗师、宝镜、每日等，隐藏 `quest2`、`session` 等内部标识。协议动作仍使用原始 ID。
- 聊天未读数仅在会话内统计新收到的 incoming `Chat.Message`；发送自己的消息不增加，进入消息页清零，最多显示 `99+`，不发送 read receipt，也不写入 localStorage。
- 断线时保留已知快照，但行囊、装备、实体、战斗、武学、聊天、地图和命令动作均禁用；非法 WebSocket 地址不会启用连接按钮。

## 本地真实运行与视口验收

使用仓库 Compose 项目 `yanhuang-stage9` 重建包含当前 `www/app` 的 `yanhuang-mud:stable` 镜像。容器健康状态为 `healthy`，8888 HTTP 页面返回 200，页面引用当前构建资源；驱动同时监听 5566、6666 和 8888。

应用内浏览器打开 `http://127.0.0.1:8888/app/index.html` 后，真实 WebSocket 已建立并收到原版欢迎/登录提示。经用户允许，使用一次性本地测试账号完成登录验收；未在本记录中保存密码，验收结束后已删除该账号的 login/user 存档、usage 日志和名字索引映射。

真实登录路径收到 `Char.Vitals`、`Char.Status`、`Room.Info`、`Room.Entities`、任务和聊天消息。已在江湖页执行 `score`、`hp`、`inventory`、`look` 等只读/低风险命令；点击真实地图出口后房间数从 2 增至 3、路线数从 0 增至 1，验证了地图动作使用服务器下发的 opaque 目标值。点击真实 NPC 后详情动作可见，再切换到“地面物品”时旧 NPC 详情被清除；行囊和装备页显示真实物品、装备槽及连接状态下可用的动作；任务页显示真实每日任务并隐藏内部分类；消息页显示真实会话消息，进入消息页后未读数清零。发送类聊天动作未在验收中触发。

## 清理与限制

一次性本地测试账号及其精确运行时数据已清理；`runtime/data/named.o` 仅保留清理前已存在的其他名字记录。新生角色没有服务器下发的武学数据，因此真实页面保持“暂无武学数据”，武学类型映射由自动化 fixture 覆盖；本次也没有进入会造成游戏状态变化的战斗或发送公聊消息，战斗目标标签、断线禁用和发送限制由自动化测试覆盖。
